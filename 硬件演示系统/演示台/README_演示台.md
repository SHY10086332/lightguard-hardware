# 硬件演示台（上位机软件）

一个页面把硬件闭环跑完整，**独立可用、不依赖任何已有软件**：

```
 ① 稳光    上位机闭环：读照度 → 发 LIGHT n → 直到落在目标 ± 容差
 ② 采集    摄像头取帧 → 存图（照度/亮度由服务端现读，写进 CSV）
 ③ 判定    内置「参考图比对」；也可手动点「判为正常/异常」
 ④ 反馈    串口发 RESULT normal|abnormal → 硬件亮绿灯/红灯 + 异常蜂鸣
 ⑤ 记录    每次判定写进 演示记录.csv（时间/图片/照度/亮度/判定/差异%）
```

---

## 一、启动

```powershell
py -3.11 -m pip install flask pyserial numpy pillow opencv-python   # 只需一次
```

| 情况 | 怎么做 |
|---|---|
| 接了 ESP32 | 双击 `0_启动演示台.bat` |
| 没接硬件（看界面） | 双击 `0_启动演示台_不接硬件.bat` |
| 命令行 | `py -3.11 demo_console.py` |

浏览器会自动打开 **http://127.0.0.1:8790/**（必须用 `127.0.0.1`，否则浏览器拒绝摄像头）。

## 二、现场演示的三步

1. **打开摄像头** → 放一张**合格品** → 点 **「设为参考图」**（此后一切以它为基准）
2. **稳光**：目标填 `300`、容差填 `20` → 点 **开始稳光** → 等右侧显示「稳光：已达标」
   （曲线会实时画出每次迭代的照度，黄色虚线是目标）
3. 换上一张**待检标签** → 按 **Enter** 拍照
   → 页面立刻给出 **✅ 正常 / ⛔ 异常**，同时**硬件亮绿灯或红灯**（异常还会短鸣）

要演示"光照不稳会误判"这件事，可以手动把亮度改掉（`LIGHT n`）再拍一张，对照差异图看效果。

> **演示前先点右上角「自检」**（10 秒）：逐项检查 串口连接 / 读取照度 / 灯带可控（顺手关灯并回读确认）
> / 参考图 / 输出目录可写 / 判定阈值。全绿再开始；"参考图未设置"是正常的（第 1 步就会设）。

## 三、闭环算法（都是踩坑之后加的）

参数在 `light_loop.py`，实测结论写进了注释：

| 机制 | 为什么要有 |
|---|---|
| 比例控制 + 单次限幅 ≤12% | 固件早期 `KP=0.06` 配 39 lx/% 的增益，环路增益 2.34，亮度在 0↔100% 之间来回振荡 |
| **自动估算增益** | 实测 lx/每1% 会随几何变（本机桌面 9.77、传感器贴近灯带 39），上位机自适应就不用重烧固件 |
| 死区 ±容差 | 到目标附近不再动，避免抖动 |
| 最小步长 1% | 误差换算小于 1% 时按 1% 走，否则取整后永远到不了目标 |
| **改亮度后等 2.2 秒再读、连读 3 次取中位** | 实测 0.8 秒读出来是错的（会读到 12.5 lx 这种乱数）；等够后 0%/25%/100% 三档极差只有 0.0~2.5 lx |

## 四、判定算法（`detect_ref.py`）

```
参考图 ─► 灰度 ─► 高斯模糊 ─► 对齐(粗搜+精修) ─► 扣亮度偏移 ─► 逐像素差
                                                    │
                            阈值化 ─► 形态学去噪 ─► 差异占比 > 阈值 ? 异常 : 正常
```

| 步骤 | 不能省的原因（都是自测里发现并修掉的） |
|---|---|
| 灰度 + 模糊 | 吸收 JPEG 压缩与传感器噪声，否则"正常"也报警 |
| **两段式对齐** | 只做 1/4 缩小图粗搜时精度只有 4 像素，残差 2 像素就把整幅图判成 12% 差异 → 加原图 ±5 像素精修 |
| **扣掉亮度中位差** | 相机自动曝光会让整幅图变亮/变暗，不归一化就"全图都是缺陷" |
| **边缘 12 像素不参与判定** | 相机轻微移动时画面边缘有内容移进/移出，那不是产品缺陷 |
| 形态学开运算 + 最小连通域 | 去掉孤立噪点，只留成片差异 |
| 阈值默认 0.25% | 自测：污点 0.78%、划痕 0.38%、断线 1.27% 都要抓到；而噪声/压缩/平移都是 0.000%，所以能压到 0.25% 而不误报 |

自测（合成图，不需要硬件）：

```powershell
py -3.11 test_detect_ref.py      # 10 项，当前全过
```

**定位说明**：这是演示台**自带**的轻量检测，用来把"拍照 → 判定 → 红绿指示"这条硬件闭环跑通。
它**不是**替换作品里的 PatchCore 异常检测模型（那是另一套系统，本软件不引用、不修改它）。

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 页面提示硬件未连接 | 串口被占用（Arduino 串口监视器、采集台还开着）→ 关掉那些程序再重启演示台 |
| 「开始稳光」报 409 | 已经有一次稳光在跑；先点「停止」 |
| 目标照度达不到 | 灯带亮度到 100% 还不够 → 目标定得太高。本机实测 100% ≈ 966 lx |
| 自动判定说没有参考图 | 先放合格品点「设为参考图」 |
| 正常品被判异常 | 阈值太严（差异占比）→ 调到 0.4~0.6；也可能是机位动了，重设参考图 |
| 关了页面灯还亮着 | 点页面上的「关灯」，或让程序正常退出（Ctrl+C 会自动关灯） |
