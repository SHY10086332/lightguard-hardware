### 2.8 T-201 MOS 模块实物识别 ✅

**背景**：需要确认手上这块模块是不是"能被 ESP32 控制的 MOS 管 PWM 驱动模块"，
而不是"手调 PWM 调速器"（后者有旋钮、没有信号输入脚，ESP32 无法控制）。

**核对方式**：用户实拍照片（正/反面各数张）+ 用户现场读丝印。

**核对结论** ✅：

| 核对项 | 结果 |
|---|---|
| 外形 | 蓝色 PCB，**4 位螺丝端子 + 2 位螺丝端子**，**无旋钮** |
| 型号字样 | 板上可读丝印含 `MOS-1`（与清单中 XY-MOS 同类） |
| 4 位端子丝印 | `DC-` `DC+` `OUT+` `OUT-`（电源进 / 负载出） |
| 2 位端子丝印 | `IN+` `IN-`（信号输入） |
| 判断 | **是标准 MOS 管 PWM 驱动模块，可用** ✅（不是旋钮调速器） |

**注意点**：`IN+` / `IN-` 的丝印是竖排小字，用户报告的顺序与照片读数存在差异，
**因此不靠"看丝印"决定极性**，改用 `mos_polarity_probe` 固件做电气自检（见 T-202）。
把 GPIO25 接到 `IN-` 等于短路到地，可能烧引脚，这一步不做赌博式判断。

**兼容性核对**：模块资料标称输入 5~36V、信号 3.3~20V、PWM 0~20kHz；
正式固件用 8kHz/8 位、本验证库同样 8kHz/8 位（2026-10-07 由 1kHz 提高）—— 均在允许范围内。

### 2.9 T-201b 电源与灯带参数核对（插 5V 之前的必做核算）✅

**依据**：用户提供的两张实物照片（适配器铭牌、灯带包装标签），2026-10-06 核对。

| 器件 | 照片上的原始信息 | 结论 |
|---|---|---|
| 5V 适配器 | `MODEL:0540`；`INPUT:AC100-240V 50/60Hz`；**`OUTPUT: 5V ⎓ 4A`**；极性符号为**中心正、外负** | 5V 4A = **20W**，满足需求 |
| 5V 灯带 | `【5V 8mm 300灯/米】1米COB灯带[高亮款] 中性光`，1 件 | 单色两线 COB，1m，中性光 ≈4000~4500K（适合检测箱） |

**电流核算**：

```
适配器可供 ：5V × 4A = 20 W
灯带预估   ：5V COB 300灯/米 高亮款 ≈ 8~12 W/米 → 1.6~2.4 A（标签未标功率，取同类经验值）
余量       ：4 A ÷ 2.4 A ≈ 1.67 倍   → 1 米整条可直接使用，无需截短
MOS 模块   ：双 MOS 设计，Rds(on) 按 10~20mΩ 估，2~3A 时发热约 0.1 W，无需散热片
```

**判定**：✅ 允许接入整条 1 米灯带。**灯带实际功率是唯一未知量**，因此首次点亮用现象兜底：

| 现象 | 含义 | 处理 |
|---|---|---|
| 模块只是温热 | 正常 | 继续 |
| 模块明显烫手（不能持续接触 3 秒） | 电流偏大 | 拔 5V，限制到 ≤50% 亮度，或只接半条 |
| 亮度忽明忽暗 / ESP32 复位 | 电源被拉低 | 拔 5V，减小负载 |

**已预判的已知现象**：5V 灯带 1 米存在**沿线压降**（远端偏暗），属正常物理现象；
若影响"5 点照度均匀性"测量，可改为**灯带两端同时接电源线**（双端供电）。

**待确认项**：DC5521 母座带线的**红/黑线对应关系**（一般红=中心正极、黑=外负）。
接反会让 MOS 模块承受反压，因此第一次上电前应目视确认线色与适配器极性符号一致。

### 2.10 T-203 / T-204 灯带 PWM 与照度闭环（2026-10-06 实测）

**接线**：`适配器红→DC+`、`黑→DC-`、`灯带红→OUT+`、`黑→OUT-`、`GPIO25→IN+`、`GND→IN-`（DC5512 母座线接适配器）。
固件：`light_pwm_test`，PWM **8 kHz / 8 位**（2026-10-07 由 1 kHz 提高），GPIO25。

#### T-203 固定阶梯调光 ✅

安全启动固件启动后亮度锁定 0%，发送命令后逐档升亮，**人工目视确认灯带亮度随 PWM 同步变化**
（`BRIGHTNESS:` 值在 0/25/50/75/100 之间变化，灯带对应变亮变暗）。
→ **PWM 调光链路（GPIO25 → MOS 模块 → 灯带）验证通过**，且 5V 适配器与 ESP32 共地成立（通过 `IN-`）。

#### T-204 照度闭环 🔶 链路通、参数需标定

**实测数据（命令 `T:0`+`A` 使亮度压到 0，`B:100` 手动锁定全亮）**：

| 状态 | BH1750 读数 | 亮度 |
|---|---|---|
| 环境（灯带灭） | **49.2 lx** | 0% |
| 灯带全亮 | **3951.7 lx** | 100% |
| 灯带贡献 | **+3902.5 lx** | — |

→ **BH1750 能看到灯带的光，灯带能被 PWM 控制，闭环的两个方向都通。**

**发现的问题（真实工程问题，已定位并修正）**：闭环进入后亮度在 0% 与 100% 之间**来回跳**：

```
BRIGHTNESS: 100 → 0 → 0 → 0 → 100 → 0 → 0 → 0 → 100 → 88 → 85 → 84 → 17 → 0 …
```

**根因**：按第一次标定的增益估算 —— `3902.5 lx ÷ 100% ≈ 39 lx / 每 1% 亮度`。
> ⚠️ 这只是**第一次标定**（传感器贴近灯带）；后来在 §2.12 重新标定为 0% → 45.8 lx、100% → 2897.5 lx（≈28.5 lx/%）。
> **lx/% 与被 BH1750 摆放位置强相关**，标定与验收请以最终箱内位置的复测值为准。
原固件比例系数 `KP = 0.06` ⇒ **环路增益 = 0.06 × 39 = 2.34 ≫ 1**，比例控制必然振荡。

**修正（第一轮迭代）**：

| 参数 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `KP` | 0.06 | **0.0025** | 按第一次标定 39 lx/% 环路增益 ≈0.098（按最终标定 28.5 lx/% 约 0.071） |
| `MAX_STEP_PCT` | 无（一步到位） | **8** | 单周期最多调 8%，防止猛冲 |
| 死区 | 无 | 第一轮 **15 lx** → 最终改为**按目标值的 ±2%**（代码中为 `DEADBAND_PCT = 2.0f`） | 进入死区就不动，消除目标点附近抖动 |

另外修正了 MODE 1 的一个交互问题：手动亮度（`B:n`）下也应持续读照度（只读不调），
方便后续标定；MODE 0 下 `B:n` 仍不触发阶梯。

**下一步（已完成）**：烧入标定后的固件后复测，三段阶跃平滑收敛、稳态偏差 ≤1.4%，结论见 §2.12。
抗干扰（遮挡/手电筒扰动）测试**尚未开展**。

### 2.11 T-301 红绿指示灯 + 有源蜂鸣器 ✅（2026-10-07）

**固件**：`indicator_test`（引脚与正式固件 **相同**：GPIO26 绿 / GPIO27 红 / GPIO32 蜂鸣器）。
⚠️ **串口协议并不相同**：`PING` 回 `LIGHTGUARD_INDICATOR`，只实现自检 `T` 与 `RESULT`，
不实现 `STATUS` / `LIGHT`，返回也不是正式固件的完整 JSON → **不能用网页直接连它**，只用于离线点亮验证。

**接线**（全部经面包板电源轨做总线）：

| 模块 | 引脚 | 接到 |
|---|---|---|
| 共阴 RGB | `G` | ESP32 **GPIO26**（绿灯 = 正常） |
| 共阴 RGB | `R` | ESP32 **GPIO27**（红灯 = 异常） |
| 共阴 RGB | `-` | 面包板**蓝轨**（GND 总线） |
| 共阴 RGB | `B` | 不接 |
| 有源蜂鸣器 | `VCC` | 面包板**红轨**（3V3 总线） |
| 有源蜂鸣器 | `GND` | 面包板**蓝轨** |
| 有源蜂鸣器 | `IN` | ESP32 **GPIO32** |

**面包板用法**：只借左下段的两条电源轨做总线 —— 蓝轨（GND）汇 5 根线，红轨（3V3）汇 3 根线；
中间孔区不使用；ESP32 / BH1750 / MOS 模块都平放在桌面，不插板。
（注意：MB-102 的电源轨**中间断开**，上下段互不相通，所有线必须插在同一段内。）

**测试方法**：连发 3 次自检命令 `T`，每轮为「绿灯 2s → 红灯 2s + 短鸣 → 全灭」。

### 2.13 T-501 相机画面 PWM 频闪条纹与消除（2026-10-07）

**现象**：接入 USB 摄像头（`USB Camera`，VID_0BDA/PID_D576）后，画面出现**固定横向明暗条纹**。

**量化方法**：从画面纸面空白区取 80px 宽竖条 → 逐行求灰度均值 → 统计波动标准差
（`ffmpeg -vf "crop=80:1080:950:0,format=gray" -f rawvideo` + PowerShell 逐行统计）。

| 帧 | 平均灰度 | 最暗 | 最亮 | **波动标准差** |
|---|---|---|---|---|
| b25-02 | 168.7 | 117.6 | 182.7 | **8.85** |
| b25-03 | 168.6 | 116.6 | 183.2 | **8.78** |
| b25-04 | 168.6 | 127.5 | 183.5 | **8.80** |

**三帧几乎相同** → 不是随机噪声，而是**固定相位图案**（相机曝光与 PWM 锁相），
符合"PWM 调光 × 卷帘快门"的频闪条纹特征；严重程度 ≈ 3.5% 满量程。

**根因**：灯带 PWM 为 **1 kHz**（周期 1 ms），画面较亮时相机选择**很短的曝光时间**，
卷帘快门逐行曝光 → 每行看到的 PWM 相位不同 → 固定横向条纹。

**修正**：PWM 频率 **1 kHz → 8 kHz**（`lightguard_esp32.ino` 与 `light_pwm_test` 同步修改）。
> ⚠️ **待复测**：上表三帧标准差（8.85 / 8.78 / 8.80）是**改频率之前**、1 kHz 下测得的数据。
> 改成 8 kHz 后**还没有重新采集逐帧数据**，"条纹幅度大幅下降"目前只是按原理推断，须在实机上复测后才能写结论。
原理：8 kHz 周期 125 µs，相机单行曝光跨越多个 PWM 周期被平均掉，条纹幅度大幅下降。
本模块标称 0~20 kHz，8 kHz 在允许范围内；**换用 ≤1 kHz 的模块须改回 1 kHz**。

**同步更新**：`固件说明.md`、`测试固件说明_硬件验证.md`、`引脚表.md`、`接线图.md`、`接线速查卡_一页版.md`。

**★ 工程约定**：**训练数据、测试数据、演示视频必须在同一套光照设置（同一 PWM 频率）下采集**，
否则模型输入分布不一致、准确率会下降。最终频率一经确定不要随意更改。

**同时确认的摄像头信息**：

| 项 | 值 |
|---|---|

#### 2.17.2 ★ 串口一开一关就会复位板子（2026-10-09 实测，重要）

**现象**：连续两次运行 `light_off.py`，两次打印的"关灯前"都是 **亮度 45%**（415 / 408 / 405 lx），
而上一次运行结束时的回读明明是 **0%**。

**结论**：这块板（CP2102 + 部分自动复位电路）**每次串口会话结束、端口关闭时都会复位一次**，
复位后固件按默认值启动 → 老固件是 45%，所以灯又亮了。

**这意味着**：
- 上位机软件里"退出时发 `LIGHT 0`"**保证不了最终状态** —— 端口一关，板子又复位；
- 唯一的根本解法是**固件默认亮度 = 0**（已改，待按 BOOT 烧录，见 2.16.5）；
- 在烧录之前，现场收尾要靠：`关灯_应急.bat` 手动关、或**拔掉灯带 5V 适配器**。

**过程纪律**：任何"读串口"的动作（包括我们自己排查）都会让板子复位并点亮灯带，
所以**排查完必须补一次 `LIGHT 0`**，并意识到端口一关它还会复位。
