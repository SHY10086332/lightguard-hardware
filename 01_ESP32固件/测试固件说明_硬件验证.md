# 硬件验证固件说明（逐项验收用）

本目录里有**两类固件**，用途不要搞混：

| 类别 | 文件 | 用途 |
|---|---|---|
| **正式固件** | `lightguard_esp32.ino` | 最终演示用：一次接管 BH1750 + 灯带 + 红绿 RGB + 蜂鸣器，配合网页串口交互 |
| **验证固件**（本文件说明的对象） | `esp32_blink_test/`、`bh1750_test/`、`light_pwm_test/`、`indicator_test/`、`mos_polarity_probe/` | 把硬件**拆成一步一步**单独验证，确认每一件器件都好，再上正式固件 |

为什么要拆开验证：硬件一次全接上时，出问题无法判断是哪个器件、哪根线、还是固件。
按下面顺序一次只验证一件事，任何一步不过就停下来查，不要往下走。

---

## 一、五个验证固件

### 1. `esp32_blink_test` —— 只验证板子本身（不接任何外设）✅ 已通过

- 接线：只插 USB 线
- 预期：板载 LED 每 500ms 亮灭；串口 115200 打印芯片型号 / 频率 / Flash / SDK / MAC
- 实测结果：见 `04_硬件验证记录/hardware-test-log.md` §2.5

### 2. `bh1750_test` —— 验证 BH1750 能否读照度

- 接线：BH1750 的 `VCC→3V3`、`GND→GND`、`SDA→GPIO21`、`SCL→GPIO22`、`ADDR→GND`（地址 `0x23`）
- 特点：**自带 BH1750 驱动，不需要在库管理器装任何库**；内置 I2C 扫描，接错线会直接报"没扫到设备"
- 预期：串口每 500ms 一行 `LUX:xxx.x`；手电筒照 → 数值明显上升；手捂住 → 明显下降

### 3. `light_pwm_test` —— 验证 PWM 调光 / 灯带

- 接线：见 `02_硬件安装与接线/接线图.md` 第 2 节（**灯带必须经 MOS 模块，不能直接接 GPIO**）
- 两种模式，用编译参数切换，不用改代码：
  - `MODE=0`（默认）固定阶梯：亮度 0→25→50→75→100% 循环，只验证"能不能调、亮不亮"
  - `MODE=1` 照度闭环：读 BH1750，自动把照度稳在目标值附近
- 串口输出：`BRIGHTNESS:xx`（MODE=1 时同时输出 `LUX:xxx.x`）
- 串口输入：`B:50` 手动设亮度、`A` 恢复自动（启动自动升降）、`S` **安全停机**（亮度归零并停止自动输出，不是查询状态）；`T:500` 设目标照度**只在 `MODE=1` 下生效**，`MODE=0` 下输入 `T:` 会得到“未知命令”

### 4. `indicator_test` —— 验证红绿灯与蜂鸣器（不接灯带和 BH1750）

- 接线：共阴 RGB 模块 `G→GPIO26`、`R→GPIO27`、`-→GND`；有源蜂鸣器 `IN→GPIO32`
- 用途：单独确认"正常亮绿 / 异常亮红 / 异常短鸣"三态，以及上电时全部熄灭
- 注意：该固件的串口协议**与正式固件不同**（`PING` 回 `LIGHTGUARD_INDICATOR`，只实现 `T` 自检与 `RESULT`，
  不实现 `STATUS` / `LIGHT`），**不能用网页直接连它**；它只用于离线点亮验证。实测记录见 `04_硬件验证记录/hardware-test-log.md` §2.11
- 说明：本固件不做"板载 LED（GPIO2）替代指示灯"的验证——它只用 GPIO26/27/32 三路输出

### 5. `mos_polarity_probe` —— 判断 MOS 模块 `IN+` / `IN-` 极性

- 用途：在只上逻辑电、不接灯带 5V 的前提下，判断控制端两个端子哪个是控制地
- 前提：**仅适用于非隔离模块**（本项目 XY-MOS 属于此类）
- 风险：判定原理只在"控制输入为高阻栅极"时成立。如果该模块的控制输入串了电阻并接三极管/光耦，
  `IN+` 侧会被 PN 结钳位而读成 LOW，可能得到"两个都接地"的假结论。
  **出现这种结果时不要据此接线**，改为查阅模块资料或换用带丝印说明的模块
- 探针使用 `GPIO26`，与 RGB 绿灯同脚：**使用前必须把 RGB 模块拔掉**，否则绿灯支路会把该脚拉低导致误判

## 三、与正式固件保持一致的约定（重要）

| 项目 | 约定值 | 说明 |
|---|---|---|
| BH1750 | `SDA=GPIO21`、`SCL=GPIO22` | 与 `固件说明.md` 一致 |
| 灯带 PWM | `GPIO25` | 与 `固件说明.md` 一致 |
| PWM 参数 | **8 kHz / 8 位** | 与正式固件保持一致；2026-10-07 由 1kHz 提到 8kHz，用于抑制相机画面的 PWM 频闪条纹（**改后尚未逐帧复测，条纹是否消除待实机确认**） |
| RGB 绿 = 正常 | `GPIO26` | ★ 与红灯不要接反 |
| RGB 红 = 异常 | `GPIO27` | ★ |
| 蜂鸣器 | `GPIO32` | 有源三针、高电平触发 |
| 串口 | 115200 8N1 | 文本行协议，见下 |

**串口协议：验证固件用的是简化文本协议**（只为在串口监视器里肉眼调试方便）：

| 方向 | 报文 | 含义 |
|---|---|---|
| ESP32 → PC | `LUX:450.2` | 当前照度（lx） |
| ESP32 → PC | `BRIGHTNESS:72` | 当前亮度（0~100） |
| PC → ESP32 | `B:72` 设亮度 / `T:500` 设目标照度（仅 MODE=1）/ `A` 恢复自动 / `S` 安全停机 |

> ⚠️ **正式固件 `lightguard_esp32.ino` 用的是另一套 JSON 协议**，网页就是按那套对接的，两者**不通用**：
>
> | 方向 | 正式固件报文 |
> |---|---|
> | PC → ESP32 | `PING` → `{"ok":true,"device":"LIGHTGUARD_ESP32"}` |
> | PC → ESP32 | `LIGHT 72`（设亮度）/ `STATUS`（查状态） |
> | PC → ESP32 | `RESULT NORMAL` / `RESULT ABNORMAL` / `RESULT IDLE` |
> | ESP32 → PC | `{"ok":true,"lux":450.2,"brightness":72,"result":"idle"}` |
>
> 所以：**写完验证固件时串口看到的是 `LUX:xxx`，烧回正式固件后看到的是 JSON**。
> 不要用网页去连验证固件，也不要用文本命令去控正式固件。

## 四、怎么烧录

### 方式 A：图形界面

1. Arduino IDE 打开对应 `.ino`（注意：**文件夹名必须和 .ino 同名**，所以每个固件是一个独立子目录）
2. 开发板选 **ESP32 Dev Module**，端口选 **COM5**
3. 点"上传"，**出现 `Connecting......` 时按住 BOOT**，看到 `Writing at 0x...` 再松开

### 方式 B：一条命令（推荐，不用掐时间）

```powershell
# 在本目录下执行；脚本会自动找串口、编译、然后一直等你按 BOOT
powershell -ExecutionPolicy Bypass -File .\flash_manual.ps1 -Sketch .\bh1750_test

# 闭环模式（不修改代码，用编译参数切换）
powershell -ExecutionPolicy Bypass -File .\flash_manual.ps1 -Sketch .\light_pwm_test -ExtraFlags "-DMODE=1"

# 只预检+编译，不烧录
powershell -ExecutionPolicy Bypass -File .\flash_manual.ps1 -Sketch .\bh1750_test -DryRun
```

脚本运行后会提示：**按住 BOOT → 按一下 EN/RST → 松开 BOOT**，然后自动连上烧录。

### ★ 为什么这块板必须手动按 BOOT

ESP32 上电瞬间采样 GPIO0：**高电平 = 运行 Flash 里的程序，低电平 = 进下载模式**。
正规 DevKit 用两个三极管自动完成，**这块板没有这段电路**（实测：esptool 默认复位报
`Wrong boot mode detected (0x13)`）。所以必须让"复位瞬间"和"BOOT 被按住"同时发生。

这是硬件设计如此，**不是板子坏了**——每次烧录按一下即可。

## 五、烧录前的安全提醒

1. **每次 ESP32 复位 / 拔插 USB 之前，先断开灯带 5V 电源**——正式固件启动默认亮度 45%，不是 0%。
2. 灯带**绝对不能**直接接 GPIO，必须经 MOS 模块/驱动模块。
3. ESP32 的 GND 必须与灯带 5V 电源**共地**，否则 PWM 失控（常亮/乱闪）。
4. 3V3 模块不要误接 5V。
